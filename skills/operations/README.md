### 与 `D:\个人知识库WB\` 卡片规范的对照（同一套方法论的两种实现）

| 工作台卡片 | 知识库卡片 | 含义 |
|---|---|---|
| `status: 已验证` | ⭐已验证 | 用过且有效 |
| `uses` | 使用记录 | 用过几次 |
| `evidence` + `source` | 来源 | 可点回原始证据 |
| `citedBy` | 关联知识 | 谁引用了它 |
| `revision` | （隐含） | 改过几版 |

**结论**：万老师早就在用的"⭐已验证 / 使用记录 / 关联知识"，和工作台的卡片 schema 是同一套方法论。只是他之前没有 `provenance`。

## provenance 规范（建议吸收进他自己的知识库）★

**这是整套东西里最值得迁移回个人知识库的一条。**

```json
"provenance": {
  "kind": "sample",        // sample | manual | agent | csv | api
  "label": "示例数据",
  "capturedAt": "2026-10-24",
  "source": "评论区",
  "url": null
}
```

| kind | 含义 | 界面颜色 |
|---|---|---|
| `sample` | 示例数据，不是你采到的 | 橙 |
| `manual` | 手动录入 | 灰 |
| `agent` | Agent 结构化出来的 | 紫 |
| `csv` | 平台导出导入 | 绿 |
| `api` | 第三方接口拉取 | 绿 |

**规则**：**没有 provenance 的条目显示"来源未知"（橙色警示），不默认当成真实数据。**
页面顶部：只要还有 `sample` 条目，就显示"这里是示例数据，还没接真实数据源"。

### 为什么这条对万老师特别重要

这正对应他最在意的两件事：
- **防编造**："有没有理论可以支撑？我不想让用户觉得这是瞎编的东西。"
- **防静电污染**：区分"真实数据 / 示例数据 / 别人的东西"三态

**建议**：给 `D:\个人知识库WB\` 的每张知识卡片加一个 `provenance` 字段。这样"这条知识是哪来的"永远可查——这和他在档案里要求的"每条观点必须带原话引用"是同一个原则。
