# 知识卡片提炼

## 何时用

- 拆解完成后（`benchmarks.json` 里有 status 为「待沉淀」的条目）
- 用户说「把这个记下来」「沉淀成卡片」
- 同一类内容连续 3 条以上表现趋同时

## 卡片类型（只能选这六个）

| type | 回答的问题 | 典型来源 |
| --- | --- | --- |
| 钩子 | 开头 3 秒怎么留住人 | 爆款拆解的 hook |
| 结构 | 一条片子怎么排 | 时间轴 + takeaway |
| 选题 | 什么题值得拍 | 多个高完播作品 |
| 证明 | 凭什么信你 | 拆解的 proof |
| CTA | 怎么让人动 | 拆解的 cta |
| 洞察 | 账号层面的规律/教训 | 自己的数据对比（可含负样本） |

## 提炼规则

1. **门槛**：要么来自 1 条已拆解的爆款，要么来自 ≥3 条自己作品的共同规律。不够就 `confidence: "低"`，并在 evidence 里写清楚样本量。
2. **结构与例证分离**：`structure` 只写可迁移的步骤（换个题材也能用）；原文、截图、具体数字一律进 `evidence`。
3. **去重**：先在 `cards.json` 里找同 type 且结构近似的卡。相似度高的不要新建，改为给旧卡 `uses + 1` 并把新来源追加到 `evidence`。
4. **反例也入库**：失败样本用 `type: "洞察"`，在 title 里写清「XX 会掉留存」。
5. **可迁移自检**：把 `structure` 里的行业词换掉，如果还能成立，才是结构；否则说明写成了例证。

## 写回 cards.json

```json
{
  "id": "hook-20261026-01",
  "type": "钩子",
  "typeTone": "svwb-p",
  "title": "反常识提问开场",
  "platform": "抖音",
  "tags": ["口播", "职场", "冷开场"],
  "structure": ["复述大众共识", "「但我见过的反例是」转折", "反例给具体数字", "承诺结论"],
  "confidence": "高",
  "confTone": "svwb-g",
  "status": "候选",
  "uses": 0,
  "evidence": "3 秒留存 68% vs 同类 41% · 来自 benchmark-0042",
  "source": "benchmark-0042",
  "citedBy": [],
  "revision": 1
}
```

- `id` 规则：`<type 英文小写>-<YYYYMMDD>-<两位序号>`
- `confidence`：单条样本 → 中；多条一致 → 高；只有 1 条且无数据 → 低
- `status` 新建一律 `候选`，等用户确认后再改 `已验证`
- 写完后把对应拆解的 `status` 改成 `已沉淀`、`statusTone` 改成 `svwb-g`

## 禁止

- 不许把整段文案塞进 `structure`。
- 不许新建与已有卡片重复的卡（先查重）。
- 不许自己把 `status` 改成「已验证」——那是用户的判断。
- 不许把推测写成 evidence（「可能会火」不是证据）。

## 完成后

一行一张：`类型 · 标题 · 置信度 · 来自哪`。最后提醒用户「这几张在知识库页可以确认或退役」。
