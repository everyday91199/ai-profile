# memory/ 记忆写入与压缩规范

> **这份文件决定整套系统会不会烂掉。** 请任何 AI（和人）在写记忆之前先读这一份。
> 谁写的：小树，2026-10-26。
> 什么时候更新：规范本身失效时（比如月文件常年超限）。

---

## 一、为什么要有这一层

原始聊天记录体积大、不能每次全塞给 AI。**真正有用的不是「把聊天记录存起来」，而是「把聊天记录压缩成 AI 读得动的记忆条目」。**

所以：`profile/` 是稳定的人格与事实（很少变），`memory/` 是流动的结论（经常变）。别把流动的写进 `profile/`。

## 二、写入时机

| 写 | 不写 |
|---|---|
| 一段对话结束**且产出了结论** | 闲聊 |
| 做出了一个**决定** | 过程讨论（没结论的） |
| 出现了一个**新事实**（新项目、新卡点、状态变化） | 重复已有结论（去更新旧条目） |
| 成长线发生了**真实变化**（含「没做到」） | 情绪发泄（除非它揭示了模式） |

## 三、条目格式（固定，便于解析和压缩）

```
日期 | 主题 | 结论 | 为什么 | 待续动作
```

**五项都要有**，缺一项就不是一条合格记忆。示例：

```
2026-10-26 | 档案分层 | 反懒惰助手归成长线，不进 projects.md | 它是自用工具不是交付产品，排优先级就变味了 | 等万老师确认它的实际形态
```

## 四、硬性限制

- **单条上限一句话。** 超过一句就拆成两条，或者进 `topics/`
- **单月文件控制在 2000 字内。** 超了就该往 `topics/` 提炼，月文件里只留指针
- **成长线单独成 topic**：`topics/个人成长.md`，格式和事业条目**分开**，不混进项目进度
- 主题重复 3 次以上 → 提炼进 `topics/<主题>.md`

## 五、提炼规则

每月末（或月文件超过 2000 字时）：
1. 把该月**重复出现**的结论合并进 `topics/`
2. 月文件里只留指针：`→ 见 topics/xxx.md`
3. 已被 `decisions.md` 收录的决定，从月文件里删掉（避免两处维护）
4. 已被 `profile/` 吸收的稳定事实，从月文件里删掉

## 六、归档规则

- `transcripts/` 里的原始记录**只留最近 N 个月**（建议 N=3）
- **入库前必须脱敏**：去掉他人姓名、联系方式、财务数据、账号信息
- `transcripts/` **默认不进公开仓库**（里面有别人的话）
- 原始素材（L3 对话）**不入库**，只保留 `sources/` 里的摘录和索引

## 七、「归档动作」清单（可执行版本）

> 大多数人是不会主动整理的。所以：**每次重要对话结束时，AI 主动提示：**
> **「要我把这次的结论写进 `memory/2026-10.md` 吗？「**

| # | 动作 | 触发时机 | 谁做 |
|---|---|---|---|
| 1 | 对话结束前，AI 主动问是否写入记忆 | 每次产出了结论的对话 | AI |
| 2 | 写入 `memory/YYYY-MM.md`，格式五段式 | 万老师说「写」 | AI |
| 3 | 涉及决定的，同步写 `profile/decisions.md` | 决定落地时 | AI |
| 4 | 涉及成长线的，写 `topics/个人成长.md` | 成长线有变化时 | AI |
| 5 | 月末提炼：`memory/YYYY-MM.md` → `topics/` | 每月末 / 文件超 2000 字 | AI |
| 6 | 更新 `START-HERE.md` | 每次改完 profile/ 或 memory/ | 跑 `scripts/build-start-here.ps1` |
| 7 | 提交到 GitHub，commit message 用约定前缀 | 每次改动 | 人（或 AI 提示） |
| 8 | 清理 `transcripts/` 超过 3 个月的原始记录 | 每季度 | 人 |

## 八、commit message 约定前缀

| 前缀 | 用途 |
|---|---|
| `决策: <一句话>` | decisions.md 的每次更新 |
| `档案: 更新身份` / `档案: 更新成长线` | identity.md / growth.md 的更新 |
| `记忆: YYYY-MM` | 月度记忆写入 |
| `素材: <来源名>` | sources/ 新增摘录 |
| `工具: <说明>` | scripts/ 改动 |

**不要 squash，不要 rebase 改写历史**——提交历史本身就是「认知变迁史」资产（见 README）。
